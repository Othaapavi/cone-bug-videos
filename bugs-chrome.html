1Scheduled date saved one day earlymedium
PB.7 / K.26 · Chrome · 1366x768 · Fail (2/2)

What is wrong: The schedule date shown in a sent request is one day earlier than the date picked (Nov 15 shown for a Nov 16 pick).

Why it is a bug: The firm is shown the wrong send date — it reads as already past — even though the backend still fires the email at the correct time.

  2. In a project, Create task > Client request > Ask a question > Continue.

8E-sign field setup drops every field on the same spotmedium
PB.4 / K.23 · Chrome · 1366x768 · Fail (2/2)

What is wrong: When adding fields to a signature request, every new field is dropped at exactly the same coordinates (Signature at 206px,366px; Date at 246px,381px) instead of being offset, so fields stack invisibly on top of each other.

Why it is a bug: The sender cannot see that multiple fields exist — they overlap perfectly — and must drag them apart one by one, which also makes it easy to leave hidden duplicate fields on the document.

Technical detail: Measured via getBoundingClientRect on the absolutely-positioned field elements: two Signature fields both at left 206 / top 366, Date field at 246 / 381. Identical coordinates on both tries.

  1. Create a client request of type e-signature and upload a PDF.
  2. In the signature field setup, add a Signature field twice, then a Date field.
  3. Look at where each field lands on the page.
Each new field is offset (cascaded) so every field is visible.All fields of the same type stack at identical coordinates — confirmed in both tries.
